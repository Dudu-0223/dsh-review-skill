# review-design

一个关注代码设计质量的 review skill：检查改动是否必要、职责是否合理，以及是否存在满足需求的更简单实现。

## 检查什么

- 不必要的接口、事件、状态、缓存和抽象。
- 重复计算、重复校验和分散的决策逻辑。
- 前端展示需求引起的后端协议或共享组件扩张。
- 功能改动中夹带的无关行为变化。
- 更简单方案的可行性、成本与限制。

遇到明确的正确性或安全问题也会报告，但不替代专项审计。

## 使用

将 [SKILL.md](SKILL.md) 加载到支持 skill 的代码代理中，技能名称为 `review-design`。

也可以直接给代理这样的任务：

> 按照 SKILL.md 审查当前分支相对 main 的完整改动。
> 按需追踪调用方，指出不必要的复杂性、职责问题和可行的简化方案。
> 只做 review，不修改代码。

请按实际情况指定比较分支或提交。

## 审查方法

先区分真实需求、实现选择和未验证的假设，再基于已有机制提出最小可行方案，与当前实现比较。

每条建议应包含具体位置、证据、影响和保留必要行为的修改方向。允许没有发现，也要求明确说明不确定性。

## 评测

使用 V4.1 Flash/high，在 20 个历史 PR、28 条人工审查目标上，每题运行 4 次：

| 配置 | 平均目标召回 ave@4 | 四次覆盖 pass@4 |
| --- | ---: | ---: |
| 不带 skill | 25.89% | 46.43% |
| 原版 review-code | 31.25% | 57.14% |
| 本仓库版本 | **32.14%** | **60.71%** |

以上选取不同实验批次，非三组同期对照；未知项经过补充复核。
题目已用于开发，评分采用同模型独立 judge，仅衡量人工意见召回，不代表误报率或整体代码审查质量。
